# 分包参数配置与直接加载

2026-10-17模型与参数说明更新；分包加载方式始于2026-10-13。参数归属于各组件。
启动节点的代码直接读取默认配置；shell和统一launch只加载环境、管理进程，
不解析参数，不生成临时YAML/JSON，也不向节点注入参数字典。

| 配置 | 文件 | 直接读取者 |
|---|---|---|
| 里程计全部参数 | `odom_ws/src/ly_lio/config/mid360.yaml` | `LyLioNode` |
| Livox ROS参数、时间转换、目标IP和启动检查 | `livox_sdk/src/livox_ros_driver2/config/mid360.yaml` | Livox驱动节点 |
| Livox网络、端口及设备参数 | `livox_sdk/src/livox_ros_driver2/config/MID360_config.json` | Livox驱动与SDK |
| lidar→云台中心安装外参 | `pcl_ws/config/lidar2baselink.yaml` | 里程计和转换节点 |
| rosbag录制选项、保存目录与QoS | `config/rosbag.yaml`（工作区外） | `ly_bag_recorder` |

修改文件后重启节点生效，无需重新构建。第一次应用此次代码改造需要构建一次。
各节点优先读取当前源码中的配置；没有源码时使用安装到包share的配置副本。
所选文件解析失败会报错；启动日志显示实际读取路径，便于确认配置来源。

此次改造增加了录包包并修改了三个工作区的节点，首次使用先增量构建：

```bash
source /opt/ros/humble/setup.bash
cd /home/hustlyrm/ly_odom/livox_sdk
colcon build --packages-select livox_ros_driver2 --parallel-workers 1 \
  --cmake-args -DROS_EDITION=ROS2 -DDISTRO_ROS=humble
source install/setup.bash
cd /home/hustlyrm/ly_odom/pcl_ws
colcon build --packages-select pcl_publisher --symlink-install --parallel-workers 1
source install/setup.bash
cd /home/hustlyrm/ly_odom/odom_ws
colcon build --packages-select ly_lio ly_bag_recorder --symlink-install --parallel-workers 1
```

## 里程计

日常只编辑包内`config/mid360.yaml`的`ly_lio.ros__parameters`。
IMU、激光、Batch、地图、初始化、话题、坐标系、输出与终端选项全部保留。
当前MID360配置与C++缺省均为`lidar_batch_duration: 0.001`秒，即1ms，范围严格为
`0 < duration < 0.010`。遇IMU事件或扫描末端提前结束；L2保留所属配置的2ms。
按2026-10-17要求，状态和P均为真正24维`[p,R,v,omega,a,g,bg,ba]`，对应`SO(3)×R^21`。
激光外参为固定配置，不进入状态/P；IMU残差最多6维，逐轴95%饱和屏蔽，不融合轮速。
激光保留每点到历史地图PCA平面的标量残差；原始点补偿到实际批末，在同一先验下
逐点计算残差/H后合并信息，一次联合更新24维状态/P。H直接覆盖`p/R/v/omega`12列，
保留原独立点噪声及PCA门控，具体公式见[建模文档的当前约定](建模.md#本项目当前实现约定)。
本轮不引入平面对平面观测，也不恢复旧的10ms相邻窗口模型。

包内配置已删除`extrinsic_est_en`、`extrinsic_rotation_cov`和`extrinsic_translation_cov`。
旧`extrinsic_est_en=false`仅作为迁移输入接受并告警，true明确启动失败；旧外参先验参数
不再适用于24维模型，显式提供会拒绝启动。ROS覆盖不能重新启用在线外参估计。

2026-10-16新增 `velocity_process_noise_rate`，单位m²/s³，必须有限且≥0，代码默认0。
它直接给三个世界系速度误差轴各增加 `rate*dt` 的协方差，不增加速度状态硬约束。
内部Q的速度块为 `rate/process_noise_reference_dt`，继续沿用现有统一传播路径；
omega/a/bg/ba仍为原来的 `Q*process_noise_reference_dt*dt`，没有迁移PLIO的整套离散方式。
reset及IMU缺段重建沿用启动时的同一噪声率。旧 `velocity_cov` 保持停用并告警，
不会将旧值解释成新参数。参数在启动时读取，修改后须重启；日志会输出实际噪声率及参考周期。
有效数值还须满足与正参考周期的比值有限，以避免内部Q溢出。
这项修复不增加2000点或其他观测上限，也不改变采样步长。
MID360保留 `velocity_process_noise_rate: 0.1`，其它设备配置未改，回退可显式设0。
该值通过的是旧30维点到面模型的两问题包及运动/近静止留出验证；本轮24维/1ms配置
须另行精度验收，不能直接沿用旧结果。旧门槛和数值见[修复记录](距离优先速度噪声修复.md)。

2026-10-16连续启动、对角平面方差及批内共享支持点噪声实验未通过精度验收，相关代码
和`continuous_initialization`、`init_imu_duration`、`plane_noise_model`参数已删除。
当前保留原启动、独立各向同性点噪声、原目标地图PCA及rate0.1，逐点使用标量点到面
测量方差；未恢复已删除的目标地图支持点噪声实验。
归档实验YAML不能作为现用配置加载。
失败证据与重新评估条件见[未采用方案记录](未采用方案记录.md)，历史数据及运行开销见
[本轮验证](连续启动与平面观测模型验证.md)。

节点代码使用ROS原生参数YAML解析。默认文件提供参数，显式ROS参数覆盖默认值，
组件容器也使用同样的加载方式。单独运行无需launch传配置：

```bash
ros2 run ly_lio ly_lio_node
```

需要独立实验配置时，使用原生ROS参数文件或参数覆盖：

```bash
ros2 run ly_lio ly_lio_node --ros-args --params-file /绝对路径/实验.yaml
ros2 run ly_lio ly_lio_node --ros-args -p terminal.enabled:=false
ros2 run ly_lio ly_lio_node --ros-args -p velocity_process_noise_rate:=0.1
```

`body_extrinsic_path`直接指向共享安装外参，默认使用package URI解析到当前源码/安装文件。
`extrinsic_R`只描述lidar→IMU测量轴旋转，不是lidar→baselink安装关系。
MID360的`extrinsic_translation_convention: imu_in_lidar`表示`extrinsic_T`填写激光系下IMU位置，
当前为`[0.011,0.02329,-0.04412]`米。内部只转换一次`t_IL=-R_IL*extrinsic_T`；
单位旋转时内部平移为`[-0.011,-0.02329,0.04412]`米，不能把这个内部平移再填入位置配置。
未声明约定时C++缺省也为`imu_in_lidar`；`lidar_in_imu`显式沿用原Point-LIO的直接平移约定，
两份当前YAML均使用`imu_in_lidar`。`extrinsic_R`只把LiDAR轴旋转至IMU轴，不随平移约定反转。

安装文件给固定`T_BL`，节点组合`T_BI=T_BL*inverse(T_IL)`并在IMU原点滤波，输出机体原点
位姿、速度与协方差。`baselink→livox_frame`仍严格为固定安装`T_BL`，不能把非零IMU原点
重新标成LiDAR原点。新模型及限制见[建模](建模.md#本项目当前实现约定)；
[30维外参文档](30维状态恢复与IMU安装外参.md)只保留历史约定和验证，不是现用配置示例。

## Livox与PTP

驱动代码直接读取本包`config/mid360.yaml`，`user_config_path`指向同目录SDK JSON。
JSON是上游SDK原生接口要求，保留持久文件直接读取，不再由启动器从YAML生成。
修改雷达IP须同步YAML的`target_ip`和JSON中的`lidar_configs[].ip`；代码会检查一致性。
接收IP和端口仅修改JSON，不会替主机设置网卡地址。

`require_ptp_sync`、`ptp_utc_offset`、`target_ip`和`ptp_interface`由驱动配置决定，
不再通过launch环境变量注入。当前默认严格PTP、TAI减37秒、目标192.168.1.3、网卡enp86s0。
驱动在初始化SDK之前只读检查已有PTP/PHC服务和主机接收IP；PTP仍由systemd独立管理。
`config_check_only`供离线核对参数/JSON使用，会跳过硬件初始化，业务运行保持false。

## 全话题录包

`config/rosbag.yaml`位于三个ROS工作区外，独立于算法与驱动配置。
Humble的`ros2 bag record`不支持完整录制参数的`--params-file`接口，
因此增加独立业务包`ly_bag_recorder`，直接调用原生`rosbag2_transport::Recorder`。
它读取此YAML并构造录制/存储选项，没有自写消息订阅或序列化。

默认录制全部话题、包含隐藏话题并持续发现，保留原始传感器best effort和
`/tf_static`的transient local QoS。保存目录按配置文件位置解析，默认`../bags`；
每次创建独立`odom_北京时间_随机后缀`目录，不覆盖旧包。Ctrl+C后调用原生stop刷新缓存、写metadata。
录包不读取键盘，避免统一运行时空格意外暂停；SIGINT和SIGTERM都能正常关闭。

```bash
ros2 run ly_bag_recorder ly_bag_recorder
```

## 统一启停

```bash
./scripts/odom.sh
# 回放原始bag或使用外部驱动，不启动Livox、不访问PTP：
./scripts/odom.sh start_lidar:=false record_bag:=false
```

统一入口仅保留`start_lidar`和`record_bag`进程开关。
原`config:=`、`config_path:=`、`bag_dir:=`、`terminal_*:=`和PTP参数注入不再使用，
日常修改对应组件文件。任一采集进程意外退出时统一关闭其余节点并等待录包写盘。
Livox已有的析构异常不在这次配置改造的修复范围内。

以前的集中配置已移除。集中配置52项断言属于此前实现的历史验证，
不能代替后续模型的检查。[Batch时长调参与零漂](Batch时长调参与零漂.md)记录旧点到面模型
的0.1ms搜索，与当前24维/1ms/固定外参配置和精度结论分开理解。

Livox驱动、转换节点、里程计和新录包包均已增量构建通过。离线启动及合成消息检查结果
保存在[分包配置验证.json](分包配置验证.json)：

  原63项参数、安装外参、SDK网络JSON和录包QoS迁移前后相同。
- 命名空间、节点重命名、多份ROS参数文件、命令行和组件NodeOptions覆盖通过；
  L2仍使用2ms及其独立机体系，10ms Batch明确拒绝启动。
- 驱动离线配置模式核对全部16项参数，不初始化SDK；目标IP与JSON不一致时拒绝启动。
  七个本轮入口均未向业务节点注入参数，RViz仅接收显示配置路径。
- 原始点云、IMU、里程计、注册云、动态TF和启动后新增隐藏话题各20条，静态TF一条；
  反序列化内容和header全部一致，启动前发布的静态TF也能录制。
  SIGINT/SIGTERM均正常退出并写出metadata；真实TTY属性不变，空格不暂停录包。
- 从`/tmp`运行统一入口，仅设`start_lidar:=false`时默认录包启用，未启动驱动。
  Ctrl+C关闭三个业务节点；单独SIGTERM录包节点也会联动关闭其余节点。
  两轮均退出0、metadata完整，并保留隐藏消息和静态TF。

本轮使用隔离ROS域和合成消息，未启动真实雷达、未操作PTP，也未重新测量零漂。
临时验证程序和合成录包已清理，只保留结果与文档。
