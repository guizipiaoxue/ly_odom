# Batch之外的逐文件审查

审查日期：2026-10-15。对象：提交 `244a15a` 的生产代码和默认配置。

后续变更：用户要求补入运动补偿导数后，代码已改为状态相关补偿，加入速度/角速度H、
修正姿态H并重算后验点。下文冻结补偿描述保留为提交`244a15a`的审查记录，
现行公式及验证见[Batch运动补偿状态雅可比](Batch运动补偿状态雅可比.md)。

本报告回答：除了把激光改为 Batch，ly_lio 还做了什么、有什么用，以及为什么不能据此预期零漂远小于 Point-LIO。
本次只新增这份审查文档，没有修改算法或配置，没有启动硬件、回放采集或操作 PTP。

## 1. 先区分三个比较对象

- **上游 Point-LIO**：工作区 `Point-LIO`，用于核对模型与原实现。
- **旧 LY 逐点版**：提交 `0066f25`，用于判断哪些变化是在改 Batch 之后才加入。
- **当前 LY**：30维状态、默认0.1ms Batch、固定非零芯片外参；不融合轮速。

与上游不同，不代表是在改 Batch 时新增。静止初始化、PCA平面、多点体素地图、真实点降采样、扫描末入图和机体杆臂输出，在旧 LY 逐点版中已经存在。

当前 Batch 是**把一小段时间内的点补偿到共同批末，在同一先验上构造点到地图平面残差，执行一次联合 EKF 更新**。没有多轮重匹配优化，没有多时刻轨迹联合优化，也没有地图协方差。

同一个先验、同一个线性模型和独立测量噪声下，联合 Kalman 更新与正确的顺序 Kalman 更新等价。顺序更新需随已得到的修正调整剩余残差。把相同的点分成一组，本身不会增加信息；实际差别来自去畸变、线性化、关联、传播分段和状态注入方式。

上游也不是任何情况下都严格“一点一更新”：`Point-LIO/include/common_lib.h:140` 的 `time_compressing()` 会将相同采样时间的点分组。上游滤波器中的 `maximum_iter=1` 也不能当成多轮优化的对照。

## 3. 按文件审查：核心滤波

### 3.1 `src/ly_lio/eskf.h`

主要位置：状态第14行、误差注入第90行附近、信息更新第110行、预测第145/156行、IMU更新第202行。

**内容与作用：**

- 保留 Point-LIO 的30维 `[p,R,R_IL,t_IL,v,omega,a,g,bg,ba]`；IMU仍是6维输出观测，单点激光仍是1维点到面约束。30维并不代表激光直接观测30个独立方向。
- Batch累加 `Λ=Σ HᵀR⁻¹H`、`η=Σ HᵀR⁻¹z`。固定外参解6维位姿子系统，在线外参解12维子系统，再通过完整P的交叉项修正其余状态。不是只更新位姿、丢掉速度和零偏。
- 使用先验子块的Cholesky白化，解 `I+LᵀΛL`；即使单批激光信息秩亏，也不直接逆Λ。公式与堆叠测量的稠密Kalman更新一致。
- 右扰动注入后，对机体旋转和外参旋转执行SO(3) reset，并处理全部交叉块；该机制在旧 LY 中已经存在。
- IMU残差为 `gyro-omega-bg` 和 `acc*scale-a-ba`，按轴屏蔽饱和测量；协方差采用展开Joseph形式。
- 保留完整的稀疏 `FPFᵀ`。加性过程噪声为 `Q*0.005*dt`，这在旧 LY 中也已存在。与上游 `Q*dt²` 的区别，只有结合其协方差传播触发方式才有意义；上游还存在按IMU频率传播的选项，不能简单说原版一定按每个点缩小Q。

**评估：** 未发现联合更新公式、旋转注入或IMU协方差公式的明确代数错误。移除速度Q确实改变模型，需单独消融。`Q*dt_ref*dt`使直接注入的噪声总量按总时间累加，但一阶F和噪声传递仍有离散近似；不同分段并非完整预测严格等价。

**不能带来的收益：** 一次联合更新不会自动消除地图误差，也不会获得多轮优化的收敛收益。

### 3.2 `src/ly_lio/estimator.cpp`

主要位置：reset第15行、单点观测第40行、联合累加第94行、Q构造在文件末尾。

**内容与作用：**

- 用历史地图5近邻做中心化PCA，拒绝重合、近共线及不够平的邻域，再检查各邻点到面的距离。上游用 `A*n=-1` 的QR拟合再归一化；PCA可表示通过坐标原点的平面。这是旧 LY 已有差异。
- 延续距离相关的残差门控。本轮将门控中的原始LiDAR点距离换为补偿后IMU点距离，是一个额外的小变化。
- 统一批内先验，构造位姿H和可选外参H，再累加信息，最后一次注入。在线外参的H保留原始LiDAR点和补偿旋转D，避免把去畸变后的点误当作原始点求外参导数。
- 激光噪声写成 `laser_point_cov*||nᵀR||²`。单位法向和合法旋转下，它就是常数 `laser_point_cov`，并非按场景质量自适应赋权。

**值得优先检查的限制：**

- 没有平面估计协方差、地图点协方差、共享地图的交叉相关项，也没有Huber/Cauchy等连续鲁棒核；目前主要依赖硬门控和常数R。
- 多个点可能反复使用同一局部平面，且共享运动补偿误差。累加时按独立标量残差处理，点多不等于独立信息同比增加；可能使P偏乐观。这是模型限制，尚不能据此认定当前零漂的主因，也不是简单堆叠才能解决的问题。
- 默认R=0.01m²，对应标量标准差0.1m。不能把该参数当标准差，也不能只拿传感器测距精度判断总残差噪声是否合适。

### 3.3 `src/ly_lio/ly_lio.cpp`

主要位置：静止初始化第73–157行、时序/Batch第159行、去畸变第211行、后验点第229行、扫描末入图第252行、断流重建第272行。

**Batch本身：**

1. 按真实时间处理IMU、点和扫描末；同时间戳先IMU后激光。
2. 从最早待处理的跟踪点或稠密点起划批，最长0.1ms，遇下一IMU或扫描末提前结束。实际批末取最后一个入批点的时间。
3. 先P后x传播到批末；固定这一先验，将点补偿到共同的批末IMU系，再联合更新一次。
4. 用后验位姿生成地图增量/注册云，扫描末才入图。在线模式只刷新标定部分，保持本批运动补偿冻结。

去畸变为 `dt=t_point-t_end≤0`，`q=Exp(omega*dt)*(R_IL*p_L+t_IL)+R_endᵀ*v_world*dt`。旋转与平移的方向核对正确，属于恒角速度/恒世界速度近似，没有高阶加速度补偿。

**关键建模近似：** 当前把先验算出的补偿D和位移b当作已知量，H只含位姿/外参直接列。它没有把补偿对 `omega`、`v` 的直接依赖以及补偿不确定度完整纳入激光观测。若使用未冻结的运动模型，世界点包含 `v*dt`，残差会有 `H_v=dt*nᵀ`，并通常有非零角速度导数。冻结模型的H正确，不代表完整运动模型的H已经覆盖这些项。0.1ms会限制这类近似的尺度，具体影响需要数据验证；不能由此直接判定静止零漂来源。

**其他已有机制与限制：**

- 静止IMU窗口估计bg、重力方向和加计模长偏差，丢弃标定前扫描，再持续静止收5帧初图。改善启动一致性，但单姿态无法独立标定全部加计零偏和倾角；没有持续ZUPT或静止位姿锁定。
- 地图整扫描冻结，避免同一扫描立即自匹配。它在旧逐点版已经存在，不能将收益全计入Batch。
- 所有跟踪点都会形成地图增量，包括没有匹配成功或被观测门控拒绝的点；入图仍受地图点距等限制。错误点可能影响后续地图；该行为同样不是Batch新增。
- 早批次入图候选不会被后续批次修正重新平滑；注册云也是各批后验拼接，不是一整帧轨迹联合优化后的结果。
- 稠密点虽然不作为激光观测，也参与批次边界，因此可能改变传播分段。0.1ms内到底有几个有效匹配点，应统计跟踪/匹配点，而不是原始点数；也可能出现只有稠密点的批次。
- 等IMU覆盖扫描末才开始处理，不等于用未来IMU倒灌更新过去；循环实际只消费事件时间内的IMU。
- IMU缺段超过0.1s或队列溢出后重建odom。评估时必须排除把重置后的新原点当作漂移减小。

### 3.4 `src/ly_lio/preprocess.cpp`

主要位置：缓冲上限第18行、点云第36行、IMU第82行。

排序、过滤非有限数据和距离、保留递增时间水位，按扫描保存跟踪点与稠密点。扫描末取距离过滤前的最后有效输入时间，避免远距离尾点被过滤后输出时间提前。拒绝重复/倒退IMU，并对缺段和缓冲溢出显式报告。

作用是保证时间覆盖与数据合法性，旧 LY 已存在。严格递增水位会跳过重叠扫描中较老的点；循环播放旧时间数据也需reset，不能直接解释成随机漏点。深队列只能缓解处理积压，不证明DDS从未丢包。

### 3.5 `src/util/voxelgrid_sampling.cpp`

主要位置：体素键第75行、采样第87行、真实代表点第119行。

空间体素中选离体素中心最近的一个真实样本，保留它原来的坐标与时间，等距按原索引确定；不把运动中不同时刻的坐标和时间平均成不存在的测量。OpenMP用于排序/计算，合并跨块重复体素。

这是旧 LY 已有的重要改进。当前0.20m降采样直接决定观测数量与几何分布；Batch不会补回已经被采样丢弃的信息。每格一个真实点也不保证各种平面方向均衡保留。

### 3.6 `src/ly_lio/voxel_map.h`

主要位置：体素索引第48行、入图第61行、近邻第89行。

使用带符号坐标体素键、多真实点存储、最小5cm点距、当前格加6个面邻格查询，在候选中选5近邻。格满后循环替换；LRU在插入时刷新，不在每次查询时刷新。与上游地图的数据结构和保留策略不同，旧 LY 已采用此结构，本轮YAML把每格20点改为32点。

作用是提供局部平面支持并控制容量。限制包括查询范围、历史点替换造成的平面变化，以及地图只保存坐标、不保存不确定度。地图会吸收估计轨迹误差；缺少绝对位置或回环约束时，Batch和逐点都不能保证长期无漂移。

### 3.7 `src/ly_lio/parameters.cpp`

参数读取时检查时长、噪声、量程、数组和旋转矩阵，拒绝非法配置；旧速度Q参数只告警、不生效，旧逐点发布开关映射为按批发布。

最重要的新边界约定是 `imu_in_lidar`：YAML的T是IMU芯片在LiDAR系的位置 `c_L`，读入时 `t_IL=-R_IL*c_L`。当前单位旋转下，内部值为 `[0.011,0.02329,-0.04412]m`，供 `p_I=R_IL*p_L+t_IL` 使用。取反只做一次。它会影响滤波几何，不能与仅改变输出坐标系混为一谈。

代码中的部分回退默认值与MID360 YAML不同，例如每格20点和最大100m。节点正常直接加载当前YAML时使用32点/50m；离线直接构造参数或不走同一加载路径时，要核对有效参数。

### 3.8 `src/ly_lio/body_output.h`

第10行起处理显式固定T_BI；第43行起处理固定T_BL并结合当前T_IL的情况。

把IMU原点状态转换到安装中心，包含位置、姿态、杆臂引起的速度和协方差。固定安装时 `T_BI=T_BL*inverse(T_IL)`，在线外参时同步重新计算，并把外参交叉项纳入输出P。

这是物理输出原点的一致性处理，基本杆臂输出在旧 LY 已存在。它不向内部滤波器增加观测，但同一姿态误差会通过杆臂表现为安装中心位置变化。评估必须使用相同安装外参和同一物理参考点。现有云台yaw拟合得到的是有效杆臂，不等于独立六自由度机械真值。

## 4. 按文件审查：输入、ROS与显示

### 4.1 `src/lidar_adapter/pointcloud_decoder.h`

读取XYZ、逐点时间和标签，检查字段布局、大小端及行填充，支持显式相对/绝对时间。当前Livox路径用 `header+timestamp*1e-9`。驱动 `lddc.cpp:329` 写入 `offset_time-base_time`，与这一解释一致。

Livox还过滤低4位噪声标记，不只是回波类别门控。过滤会改变观测集合，应在与参考对照时统一。时间正确是必要条件；PTP锁定不等于已经标定物理采样时差，静止也无法验证动态时间标定。

### 4.2 `src/ly_lio_node.cpp`

默认配置加载第84行、安装外参第205行、IMU订阅第376行、机体发布第422行。

新增所属YAML直接加载，源码优先、包share回退，ROS显式参数再覆盖。输入仍是原始 `/livox/lidar`、`/livox/imu`，没有把已转换到baselink的数据再次送进内部滤波。IMU best effort队列加深到1000。

统一发布机体Odom、TF和注册云的传感器时间；固定T_BL发布实际安装TF，显式固定T_BI配合在线T_IL时使用动态传感器TF。reset同步清理Path和导出地图。

用途是避免重复外参、排队损失、时间戳和坐标系错配；不形成额外定位约束。默认约10Hz扫描末输出与内部激光更新频率是两回事。注册云/Path订阅、录包和导出会增加负载，实机与核心离线结果不能默认相同。

### 4.3 `src/terminal_dashboard.cpp`

第72行确定初始参考，第78行累计距离，第195行进行B0显示变换。

首个有效机体位姿建立初始机体显示系，终端展示 `T0⁻¹*T`，不写回滤波或ROS TF。`Distance Traveled` 用10cm累计门限，可能长期显示0而实际有厘米级变化；判断零漂应看位置、`Distance to Origin`和Odometry，不能看这个累计量。GOOD只代表流程状态，不是精度认证。

### 4.4 `src/util/pointcloud_mapping.cpp`

这里做体素内均值，但用于**保存/导出的地图**。它不是 `voxel_map.h` 中用于匹配的历史地图，也不是滤波前真实点采样。不会通过均值地图反馈修正滤波；主要影响导出内容和运行负载。

### 4.5 `src/io/pcd_io.cpp`

PCD读写和LZF压缩，包含头部/长度/读写结果检查。节点的保存路径不构成定位约束；没有在当前运行流程中用它加载一份绝对地图做重定位。与静止零漂没有直接模型联系。

## 6. 当前参数与历史结果，不能混用

当前默认MID360参数：Batch0.1ms，采样0.20m，地图0.20m/32点/最小5cm，激光R=0.01，陀螺R=0.01，加计R=0.01；Q仅omega/a/bg/ba，分别1000/500/0.0001/0.0001，参考周期0.005s。固定非零芯片外参，不在线估计，不融合轮速。

发现一处**复现依据不一致**：`docs/最新录包IMU与激光贡献分析.md` 第9–23行称录制参数与“当前”一致，但列出激光R=0.001、陀螺R=0.001、采样0.10m；当前YAML分别为0.01、0.01、0.20m。这不证明当时录包记录有误，但说明文中的“当前”只适用于当时快照。不能直接把该文约223秒的精度当成本次检出配置的验收。

`docs/Batch时长调参与零漂.md` 则明确属于历史24维模型。其同源600秒结果为：

| 时长 | 位置RMS cm | 含义 |
|---|---:|---|
| 2ms | 0.492328 | 当时基线 |
| 0.1ms | 0.461551 | 相对2ms降低6.25% |
| 1/2.5µs | 0.466988 | 每批至多一个原始点的近单点极限 |

同一Batch实现中，0.1ms相对近单点极限仅降低约1.16%的位置RMS。这个近单点极限仍保留LY的其他模型/工程差异，**不等于原版Point-LIO**。这些结果支持“批长会影响结果”，不支持“Batch必然远优于逐点”，也不能替代当前30维/非零外参的实机结论。

## 7. 本次核对覆盖与结论边界

除了逐文件阅读及两个提交间对照，本次用stdin运行独立NumPy公式核对，没有保留验证程序：

| 核对 | 数量 | 最大绝对差 |
|---|---:|---:|
| 白化信息更新与稠密Kalman的状态修正 | 64组，固定6维/在线12维各32组 | 4.41e-14 |
| 同上，后验P | 同上 | 2.67e-14 |
| 冻结D/b下位姿与外参H中心有限差分 | 64组 | 5.60e-10 |
| IMU屏蔽轴的展开Joseph协方差 | 64种屏蔽组合 | 4.44e-16 |

这是公式层面的独立核对，不是本次重新执行生产C++数值测试、构建或ROS实机验收。尤其“冻结H正确”不能推广成完整去畸变不确定性已建模。

目前没有证据把某一处实现认定为当前零漂的唯一主因。优先关注的事项依次是：有效参数与比较基线不一致；Batch之外的Q/传播/地图/外参变化；冻结补偿的条件模型；共享平面和地图误差按独立点处理；短批有效几何支持是否足够。

## 8. 建议的下一轮对照顺序

1. 固定当前30维、同一非零外参、初始化前缀、输入顺序、采样、地图、Q/R和输出中心，保存实际生效参数。用同源数据比较，另留一份未参与调参的数据验证。
2. 先冻结相同的点、平面、H和残差，比较一次联合更新与正确调整残差的顺序更新，确认只改“求解形式”应等价。
3. 再比较“逐点真实时间重线性化”与“批末冻结补偿”，将时序/非线性差异与线性求解差异分开。统计每批跟踪点数、匹配点数及信息矩阵特征值，不能只记录配置批长。
4. 将速度Q、先P后x、地图20/32点、距离100/50m分别消融，不同时改变外参。当前用户指定的0.1ms和非零外参保持为主配置，对照仅作为独立实验。
5. 若前述对照仍显示异常，再验证补偿对v/omega的导数/不确定度，以及地图/平面相关性的处理。新增复杂模型前，先证明它解决了哪一种可重复误差。

评价同时报告位置RMS/最大/首末窗口均值、姿态变化、输出时间覆盖、重置和运行耗时。静止结果不能代替运动精度，降低P或让输出更平滑也不等于降低真实误差。
